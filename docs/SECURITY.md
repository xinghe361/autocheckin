# 安全设计说明

本文档说明本项目在安全方面的**设计与使用方法**。

---

## 一、凭据是怎么存的

| 内容 | 存放位置 | 保护方式 |
|---|---|---|
| 站点密码、站点 Cookie、DeepSeek Key、WebDAV 密码、访问口令 | `config.json` | Fernet 加密（AES-128-CBC + HMAC），文件权限 600 |
| **通知渠道凭据**（pushplus / 企业微信 / Telegram） | `config.json` | **Fernet 加密** —— 明文只在内存，落盘只有密文 |
| **代理地址里的账号密码**（通知级 / 渠道级） | `config.json` | **Fernet 加密** —— 同上 |
| 加密密钥 | `AUTOCHECKIN_KEY` 环境变量，或 `DATA_DIR/secret.key` | 权限 600；**单独存放** |
| 会话令牌 | 只存 SHA-256 哈希 | 配置里没有令牌明文 |
| 运行状态 | `state.json` | 权限 600；不含密码/Key，但会含失败详情（见下） |

**老配置会自动迁移**：如果你的 `config.json` 里这些凭据还是明文（1.4.2 及
更早的版本就是这样），程序读的时候照常可用，**下次保存设置时自动加密**。
手工确认方式：搜一下 `config.json` 里有没有 `"pushplus_token": "..."` 这种
明文键；加密后这些键会消失，只剩下 `*_enc` 结尾的密文。

**密钥为什么单独一个文件**：备份里存的是**密文**。若把密钥与密文放进同一个
备份对象，等于把锁和钥匙捆在一起，加密就失去了意义。所以：

- `config.json` / 备份文件里只有密文
- `encryption-key.txt` 是独立文件，**是否上传由你显式勾选**（默认关闭）
- 界面显示密钥指纹，便于核对两台机器是否同一密钥，又不泄露密钥本身

**`state.json` 的注意点**：站点密码与 Key 确实不在里面，权限也是 600。
但它会保存**失败详情**——例如上游返回的报错正文片段（`last_ai_error`、
`cookie_error`）。那些内容可能含对方服务器的提示信息，所以它**适合和
`config.json` 一起备份**，但不宜公开分发。页面上的"运行状态可安全备份"
说的就是这个意思：同机备份没问题，公开分享请先看一眼内容。

## 已知不足（如实列出，避免误解）

| 项 | 现状 | 影响 |
|---|---|---|
| 会话令牌有效期 | 只写在 Cookie 的 `Max-Age`（30 天）上，服务端不校验时间 | 明文 http 下若令牌被嗅探，在手动吊销前一直有效。**建议改口令**让旧会话全部失效 |
| 界面传输 | 明文 http | 设计取舍：局域网自用、不暴露公网。切勿映射到公网，也不要在不可信网络使用 |
| 代理环境变量 | 已废弃 | 代理改为**只在网页「设置 → 网络」**里配。以前环境变量也能设，两处打架会导致"网页改完不生效" |

**密钥丢了会怎样**：已保存的站点密码与 API Key 解不开。此时会得到明确报错
（提示"无法解密"并让你重新填写），而不是笼统的"登录失败"。

## 二、访问控制

网页界面默认需要登录。首次访问会引导你设置一个访问口令（至少 6 位）。

| 措施 | 说明 |
|---|---|
| 口令存储 | Fernet 加密后写入配置，不存明文 |
| 会话令牌 | 只存 SHA-256 哈希，不存令牌本身 |
| 令牌传递 | HttpOnly + SameSite=Lax Cookie；**不放在 URL 里** |
| 口令比较 | 使用常数时间比较函数 |
| 登录限速 | 5 分钟内失败 10 次即拒绝 |
| 改口令 | 所有旧会话立即失效 |
| 匿名可访问 | 仅 `/healthz`（容器健康检查）与 `/api/auth/state`（登录页） |

口令只用于进入本界面，**与你的各站点账号无关**。

### 首次启动请立刻完成初始化

容器第一次启动时还没有口令。请**立即打开网页完成初始化设置**，
不要让它长时间停留在这个状态。

### 忘记口令怎么办

在 NAS 上编辑数据目录下的 `config.json`：

```bash
# 方式一：关闭访问控制（改完重启容器生效）
"auth_required": false

# 方式二：清空已设口令，重启后会重新引导设置
"auth_password_enc": ""
```

⚠️ **方式二现在不一定有效**：为了让"配置损坏"不被误判成"全新安装"
（那种情况会被局域网里第一个访问者抢注口令接管），程序会持久化记录
"这台实例曾经初始化过"。只要 `DATA_DIR` 里存在以下任一项，就不会再
进入首次设置流程，需要改用**方式一**（改 `AUTOCHECKIN_KEY` 或删
`secret.key`）或直接把 `config.json` 整个删掉：

- `config.json`
- `config.json.broken.*`（配置损坏时的现场备份）
- `config.json.unreadable`（损坏哨兵）

## 三、网络安全

- **全站统一走代理**（你的代理已做分流，填代理地址即可）
- **每个通知渠道可单独选择走不走代理**
- **通知渠道凭据、代理账密都已加密存盘**（密文，明文只在内存）
- **不要把本服务的端口暴露到公网**。它设计为在内网使用；
  公网暴露会显著放大风险，且与"关闭沙箱"叠加后后果更重

## 四、容器加固

`docker-compose.yml` 默认已带：

```yaml
security_opt:
  - no-new-privileges:true   # 容器内进程无法通过 setuid 等方式提权
shm_size: "256m"             # 给浏览器留足 /dev/shm（镜像默认不含浏览器，见下）
```

**镜像默认不含浏览器**（1.4.3 起）：内置站点全部走纯 HTTP 请求；抓 Cookie
靠用户浏览器里的扩展；录制脚本注入在用户浏览器的 iframe 里 —— 都不需要
容器内浏览器。少一个常驻的浏览器进程，容器要维护的东西也就少一块。

如果你按 README 的「需要浏览器怎么办」把浏览器加回来，注意：容器里
Chromium 的沙箱常因缺少内核特性（`CAP_SYS_ADMIN`、seccomp 限制、或宿主关闭了
`unprivileged_userns_clone`）而无法启动，因此需要用 `--no-sandbox`；
`no-new-privileges` 是对此的补偿。

**如果想进一步收紧**，可以改为非 root 运行：

```yaml
user: "1000:1000"
security_opt:
  - no-new-privileges:true
```

配套需要把宿主机数据目录属主改成 1000（否则启动即权限拒绝）：

```bash
sudo chown -R 1000:1000 /你的数据目录
```

> 三者互斥，最多同时满足两个：**非 root**、**开启 Chromium 沙箱**、
> **免额外配置**。因为 Chromium 的沙箱辅助程序需要 setuid（即需要 root）。

## 五、依赖与供应链

| 项 | 状态 |
|---|---|
| `cryptography` | 固定 `==43.0.3` |
| 浏览器 | **镜像默认不含**（1.4.3 起）。内置站点走纯请求，用不到它 |
| 基础镜像 | 固定 tag `python:3.12-slim`（非 latest）|
| 其余依赖 | **全部为 Python 标准库**，无额外第三方包 |

> **基础镜像为什么从 Playwright 换成了 slim**：Playwright 官方镜像自带
> Chromium / Firefox / WebKit 共约 1.5GB，而本项目的三个内置站点完全走
> 纯 HTTP 请求（不需要浏览器），抓 Cookie 与录制又都发生在**用户自己的
> 浏览器**里。关键点是：**在后面层里 `rm -rf` 浏览器并不会减小镜像体积** ——
> 那些文件仍留在基础镜像的层里，拉取时照样下载（实测浏览器所在层 616MB
> 原封不动）。所以唯一有效的瘦身办法是换掉带浏览器的基础镜像。

纯标准库是刻意选择：HTTP 服务、JSON 解析、WebDAV 客户端等都不引入依赖，
攻击面因此小很多。

## 六、提交前的自查

```bash
python selfcheck.py            # 检查敏感文件、编码、关键文件完整性
python docs/check_compose.py   # 校验 compose 结构（缩进、关键字段）
python -m unittest discover -s tests
```

`selfcheck.py` 会扫描仓库里是否误留了密钥、密码、token 等敏感内容。
